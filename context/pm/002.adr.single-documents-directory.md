status: accepted

## Context

Where documents may live on disk, and what the scanner is allowed to
walk. Project directories also contain build artifacts and dependency
trees (a `node_modules` will eventually appear near anything), so
scanning must never recurse blindly.

## Decision

`pm.json` declares a single required `directory`. The scanner reads
exactly two levels: entries of that root, and files inside managed
directories (`{id}.{slug}/` groups, plus the legacy `{id}.{tag}.{slug}/`
form). Every other directory is ignored, never entered. Placement is
deterministic: child of a document → same directory as the parent;
child of a group → inside the group; no parent → the root.

## Consequences

Easier: scanning is fast and safe by construction; there is exactly one
place groups can live, so document placement has one answer. Harder:
documents outside the root are invisible — projects that kept a second
documents area must move those files in.

## Alternatives considered

- **Multiple roots (`string[]`)** — pros: supports split areas such as
  a separate notes directory. Rejected: cannot express which root a new
  document should go to.
- **Per-type directory with a default** — pros: familiar, keeps types
  physically sorted. Rejected: parent-based placement overrides it
  whenever a parent exists, making the configured directory a lie.
