---
title: Type lives in the filename only
status: accepted
created_on: 2026-08-27
---
## Context

Where a document's type is stored: the filename tag, the frontmatter,
or both.

## Decision

The filename tag is the single source of a document's type. Changing
the type means renaming the file (`pm edit <id> --type <t>` does it in
place). References are ID-authoritative, so refs holding a stale tag
hint keep resolving; `pm tidy` rewrites them to the current canonical
form.

## Consequences

Easier: no drift possible, the type is visible in every path and
listing, and greppable without opening files. Harder: a type change
touches the filesystem instead of one YAML line.

## Alternatives considered

- **Frontmatter `type` with the filename as a cache** — pros: type
  edits stay inside the file like every other metadata change.
  Rejected: an exact lossless duplicate creates two sources of truth
  needing a merge rule, and the natural "frontmatter wins" rule would
  make tidy rename files as a side effect of a forgotten YAML edit.
  (Unlike title/slug, where the slug is a lossy projection and the heal
  direction is unambiguous.)
