Findings from a scan of 41 agent sessions (26 Claude Code, 15 Codex) that used
pm between 2026-09-15 and 2026-09-29, mostly in aitx-pub, plus otta-backend,
pop-performance-navigator, gen_mcp, jsv and this repo. About 280 pm calls; no
pm error outside legacy configs, no invented commands or flags, no user
complaint about pm.

## What works

- Orientation in one or two calls: "let's do pm 056" → `pm show 056 && pm info
  && pm current`, then real work.
- `pm new` output (guide path + "Body is empty") was followed every time: guide
  read, real body written, no empty docs since v0.13.1.
- IDs make delegation cheap: one `pm which` with 7 IDs in a subagent; bare
  "pm 051" sub-sessions ran to `pm done`.
- `depends:` sequencing and `pm done X && pm ready` let agents explain what got
  unblocked.
- Specs serve as cross-session memory; `pm ready` prevented a duplicate spec.
- `pm tidy` dry-run default stopped a destructive remap.

## Recurring friction

Each item has a child task. Not kept: legacy `doctypes` migration hints (only
the author has old configs).

- Finished work left open (043, 049, 055, 046) and `current` pointing at done
  docs.
- `depends` invisible in `pm show`, silently hidden by `pm ready`, written as a
  scalar by `--set`.
- `pm --help` has no command descriptions (15+ probes).
- pm-guide loaded for unrelated work because of its "whenever you detect
  pm.json" trigger.
- `pm new … && pm edit 053` edited the wrong doc: a parallel session had taken
  053.
- Output rough edges: tidy dry-run tail read as "tree is tidy", silent empty
  lists, long `pm info` piped through `head`, ANSI codes (task 010).
