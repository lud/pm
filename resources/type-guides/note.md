# Working with notes

A note captures anything worth keeping that is not work to be done: findings, gotchas,
references, domain knowledge. No workflow — most notes stay at their default status
forever, and that is fine.

Name the subject, not the occasion ("Encoding pitfalls in CSV export", not "Notes from
Tuesday") — the title is how it gets found. Rewrite in place when knowledge changes. When
a note stops being relevant, archive it (`pm done <id>` sets `archived`) to clear it from
listings, or delete the file (git remembers).
